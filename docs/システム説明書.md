# Snipdash システム説明書

はじめての方向けに、Snipdash が「何で・どう使えて・どう作られているか」を一通り説明します。
（細かい仕様は [`仕様書.md`](仕様書.md)、開発の進め方は [`../CONTRIBUTING.md`](../CONTRIBUTING.md) を参照）

---

## 1. Snipdash とは

**ローカルファーストな“スニペット & タスクのダッシュボード”デスクトップアプリ**です。

- よく使う**定型文・コマンド・リンク・ToDo** を「カード」として並べ、**ワンクリックでコピー／起動**できます。
- カードは**12列グリッド**上に自由に配置し、**タブ（盤面）**で切り替えます。
- データは**ローカルの単一ファイル `workspace.json`** だけ。**サーバーもネットワーク通信もありません**（プライバシーと速さが利点）。
- 日本語 / 英語の**バイリンガル**対応。

> 一言でいうと「自分専用の、コピペと作業の発射台」です。

## 2. 基本のしくみ（用語）

| 用語 | 意味 |
|---|---|
| **盤面（ボード）** | 画面上部のタブ。用途ごとにカード群を分けて切り替える。タブごとに色を付けられる。 |
| **カード** | グリッド上の1枚。下記5種類。 |
| **使用モード / 編集モード** | 右上の ✏️ で切替。**使用モード**＝コピーや起動など普段使い。**編集モード**＝カードの追加・移動・リサイズ・本文編集。 |
| **グリッド** | 12列のマス目。編集モードでカードをドラッグ／リサイズするとマスにスナップする。 |
| **テンプレート変数** | `{{TODAY}}` `{{NOW}}` `{{UUID}}` など。**コピーした瞬間に**実際の値へ展開される（カード本文には元のまま残る）。 |

### カードの種類
1. **テキスト** — プレーンな定型文。
2. **Markdown（リッチ）** — 見出し・箇条書き・リンク・画像・コピーボタンを含む書式付き。
3. **コード** — 言語指定付きのコードスニペット。
4. **ToDo** — iOS 風の丸チェック。期限・リマインダー設定、完了の表示/非表示トグル付き。
5. **スペーサー / 見出し** — 余白や見出しでレイアウトを整える。

### リンクと埋め込み（Markdown カード内）
- 本文に `[表示名|リンク先]` と書くと**インラインのリンク**になります。
- リンク先は **URL**（ブラウザで開く）／**ファイル**（既定アプリで開く）／**フォルダ**（エクスプローラ等で開く）／**アプリ**（起動）。
- `![代替文字|幅x高さ]` で**画像をサイズ指定して埋め込み**。
- `[[表示|コピー対象]]` で**その場のコピーボタン**を設置。

## 3. 主な機能

- **今日ビュー（📅）** — 全盤面の ToDo を横断し、**期限切れ / 今日 / まもなく**に集約。ツールバーに残数バッジ。クリックで該当カードへジャンプ、チェックで完了。
- **コマンドパレット（`Ctrl+K`）** — コマンドと全カード/盤面を**ファジー検索**。Enter で既定動作（コピー可ならコピー、不可ならジャンプ）、`Alt+Enter` で逆。
- **クイックキャプチャ（`Ctrl+Shift+Space`）** — どのアプリからでも前面化して1行入力 → **Inbox 盤面**に即追加。連続入力可。
- **ポモドーロ／フォーカスタイマー** — ツールバー常駐。集中/休憩を計測し、終了で通知＋自動で次フェーズ。時間は設定で変更可。
- **リマインダー** — ToDo の期限が近づく/過ぎると OS 通知＋アプリ内トーストで知らせる。

## 4. クイックスタート

1. アプリを起動すると最後の `workspace.json` が読み込まれます（初回はサンプルが入ります）。
2. 右上の ✏️ で**編集モード**へ。「＋ カードを追加」から種類を選んで配置。
3. カードをドラッグで移動、四隅でリサイズ（マスにスナップ）。本文をクリックして編集。
4. ✏️ を戻して**使用モード**に。カード右上の**コピー**で本文を（変数展開して）クリップボードへ。
5. タブ（盤面）を増やして用途ごとに整理。`Ctrl+K` でどこへでも素早く移動。

## 5. キーボードショートカット

| キー | 動作 |
|---|---|
| `Ctrl + K` | コマンドパレットを開く |
| `Ctrl + Shift + Space` | クイックキャプチャ（グローバル／設定で変更可） |
| `Ctrl + PageUp` / `PageDown` | 前 / 次のタブへ |
| `Ctrl + 1〜9`（テンキー含む） | 左から N 番目のタブへ |
| `Ctrl + E` | 編集 / 使用モード切替 |
| `Ctrl + T` | 新しいタブ |
| `Ctrl + W` | 現在のタブを削除 |
| `Ctrl + ,` | 設定の開閉 |
| `F2` | タブ名を変更 |
| `Esc` | メニュー・パネルを閉じる |

設定（⚙）では**テーマ／言語／常に最前面／既定の通知タイミング／グローバルホットキー／ポモドーロ時間**を変更できます。

## 6. データと安全性

- 保存先は OS のアプリデータ領域の `Snipdash/`（例: Windows は `%APPDATA%`、macOS は `~/Library/Application Support`）配下の `workspace.json`。
- 保存は**アトミック書き込み**（一時ファイル → 置換）＋**3世代の `.bak` バックアップ**。
- ファイルが壊れている場合はバックアップから復旧、できなければ `.json.corrupt` に退避して新規ワークスペースを作り直すため、**データを失いにくい**設計です。
- すべてローカル完結。外部送信はありません。

## 7. システム構成（開発者・オーナー向け）

技術スタック: **Tauri v2 + React + Rust**、**pnpm モノレポ**。3層構成です。

```
Snipdash/
├─ crates/snipdash-core/   … ① ドメインの中核（Rust・UI/IO非依存）
│                              型定義・検証・直列化・スキーマ移行
├─ packages/snipdash-sdk/  … ② TypeScript SDK
│                              ①と同形のTS型・テンプレート展開・Tauri呼び出しラッパ
└─ apps/desktop/           … ③ アプリ本体
   ├─ src/                    React フロント（画面）
   └─ src-tauri/              Rust バックエンド（OS連携）
```

押さえるべき設計の柱：
- **Rust ⇄ TS の同形契約**: ドメイン型は `crates/snipdash-core/src/model.rs` と `packages/snipdash-sdk/src/types.ts` に**二重定義**し、JSON 形状を一致させる（その JSON が**保存形式そのもの**かつ **IPC ペイロード**）。
- **信頼境界**: 画面（WebView）は OS 資源（ファイル/クリップボード/起動）に**直接触れない**。すべて `src-tauri` の Tauri コマンド経由で、起動対象などは Rust 側で**再検証**。権限は最小限（`capabilities/default.json`）。
- **状態管理**: フロントは単一の Zustand ストアに `Workspace` を保持し、変更は `commit()` 経由で**400msデバウンス保存**。Tauri 外（ブラウザ/デモ）ではサンプルで動き、保存はスキップ。

> 詳細は [`仕様書.md`](仕様書.md)（製品仕様）と、リポジトリ直下の `CLAUDE.md`（コード規約）を参照。

## 8. 動かす・ビルドする

```bash
pnpm install        # 依存をインストール
pnpm dev            # 開発起動（tauri dev）
pnpm build          # SDK → フロントをビルド
pnpm tauri build    # 配布用インストーラを生成
pnpm typecheck      # 型チェック
pnpm test           # JS/TS テスト
pnpm test:core      # Rust コアのテスト
```

- 起動には各 OS の [Tauri 前提条件](https://tauri.app/start/prerequisites/) と GUI/WebView が必要です。
- **グローバルホットキーやウィンドウ制御は実機（`pnpm tauri dev`）でのみ動作**します。
- Docker で開発したい場合は [`Docker開発環境.md`](Docker開発環境.md) を参照。
