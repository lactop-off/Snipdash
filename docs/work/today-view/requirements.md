# 要件定義 — 「今日」横断タスクビュー

> フェーズ: 要件定義 (pm) ／ 状態: **人間承認待ち** ／ feature slug: `today-view`

## ゴール & ユーザー価値
作業中に「**今やるべきこと**」を一望できるようにする。todo 項目は各盤面のカードに散らばっているため、期限が迫る/過ぎた項目を**盤面横断で1か所に集約**し、そこで消化（完了）できるようにする。

## スコープ
**In scope**
- 全盤面(`boards`)の全 todo カード(`payload.mode === "todo"`)の `items` を走査し、**未完了(`done=false`)かつ期限(`due`)あり**の項目を集約表示。
- 緊急度で分類して表示（期限切れ / 今日 / まもなく）。
- 集約ビュー上での操作：完了トグル、該当カード・盤面へジャンプ。
- ja/en 両対応。開閉手段（ヘッダーのボタン等。具体UIは基本設計へ）。

**Out of scope**
- 期限なし todo の集約（→ open question Q3）。
- 新規タスク作成（#3 クイックキャプチャで扱う）。
- 高度な並べ替え/フィルタのカスタム、タグ/担当者等。
- 集約ビューからのテキスト編集（完了トグルと期限編集導線のみ。本文編集は該当カードで）。

## 機能要件 (FR)
- **FR-1** 全 `boards` の全 todo カードの `items` を走査し、未完了かつ `due` ありの項目を収集する。
- **FR-2** 各項目の緊急度を SDK の `dueUrgency(item, now)` で算出し、**期限切れ(overdue) / 今日(today) / まもなく(soon)** に分類する。"today" の定義＝本日中（ローカル時刻で当日の 23:59 まで）。soon は既定の近接窓（暫定1時間、Q1）。
- **FR-3** 各分類内は `due` 昇順に並べる。
- **FR-4** 各項目に「テキスト」「所属（カードの label ＋ 盤面名）」「期限表示」「緊急度」を表示する。
- **FR-5** 項目クリックで該当**盤面に切り替え**、対象カードを視認できる状態にする（スクロール/一時ハイライト等、手段は基本設計）。
- **FR-6** 項目のチェックで `done` をトグル（`store.updateCard` 経由で即保存）。完了した項目は集約ビューから外れる。
- **FR-7** 対象 0 件のとき空状態メッセージを表示。
- **FR-8** `workspace` の変更にリアルタイム追従（zustand 購読）。
- **FR-9** 開閉手段を用意（最低限ヘッダーのアイコンボタン。ショートカット併用は任意 → Q5）。

## 受け入れ基準 / Definition of Done
- `pnpm typecheck` / 該当する `cargo test -p snipdash-core`（スキーマ変更時）/ SDK vitest / `pnpm --filter @snipdash/desktop build:vite` が通る。
- overdue / today / soon の3分類に正しく振り分く（境界値：今ちょうど・本日終端・soon 閾値を確認）。
- 期限なし・完了済みの項目は既定で出ない。
- 項目クリックで該当盤面に切り替わり、対象カードが視認できる。
- チェックで `done` がトグル＆保存され、ビューから消える。
- 0 件で空状態が出る。ja/en 双方で表示が正しい。
- **実機検証（QA/Playwright）**：期限付き todo を用意 → 今日ビューを開く → 分類と件数を確認 → チェックで消える → ジャンプで盤面が変わる、を観察。
- 非 Tauri デモパスでも動作（保存は skip される）。

## 制約
- **Rust⇄TS lockstep**：本機能は既存 `due` 等を「読むだけ」の派生計算が中心で、**新規スキーマは原則不要**の見込み。ビューの開閉状態を永続したい場合のみ `Settings` に optional 追加を検討（→ tech-lead 判断）。
- 最小権限・i18n(ja/en)・デモパス維持（CLAUDE.md 準拠）。
- パフォーマンス：項目数に対し O(n) の軽量走査。集約はメモ化推奨。

## 人間（オーナー）への Open Questions
1. **soon の閾値**：既定 1 時間でよいか？設定で変更可能にするか（既存の `defaultRemindBefore` と揃える案も）。
2. **「今日」の扱い**：当日中（〜23:59）の未到来分も「今日」に含めるか、それとも overdue＋soon のみにするか。
3. **期限なし todo**：未完了で期限なしの項目を「未整理」枠として別表示するか（今回の既定は**出さない**）。
4. **今日の達成**：今日 `done` にした項目を達成感のため小セクションで見せるか（既定は**出さない**）。
5. **開き方/ショートカット**：ヘッダーボタンに加えショートカットを割当てるか（Ctrl 系は既に多いので候補要相談）。
6. **表示形態の方向性**：モーダル / 右サイドパネル / 専用タブ のどれが好みか（最終案は基本設計でデザイナーが提示。希望があれば）。
